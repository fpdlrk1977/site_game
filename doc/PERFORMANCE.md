# PERFORMANCE: 최적화 및 제약 사항 규격서

AI가 코드를 짤 때 렌더링 성능이 떨어지는 코드를 생성하지 못하도록 제한하는 방어벽 문서이다.

## 1. 드로우콜(Draw Call) 제약 및 Instancing 규칙
- AI는 동일한 `assetId`를 가진 정적(Static) 오브젝트가 3개 이상 배치되는 경우, 단일 `mesh`를 수백 번 호출하는 코드를 짜서는 안 된다.
- 동일 에셋 군집은 Three.js의 `InstancedMesh`를 동적으로 생성하여 단 1회의 드로우콜로 통합 처리하는 로직을 자동 빌드하도록 코드를 강제한다.

## 2. 에셋 파이프라인 제약
- 시스템에 업로드되는 모든 `.glb` 파일은 업로드 완료 트리거 시 클라우드 람다(Lambda) 또는 백엔드 워커에서 `gltf-pipeline`을 경유하여 Draco 압축 파일로 강제 트랜스코딩되어야 한다.
- 클라이언트 뷰어는 `setDecoderPath`가 지정된 DracoDecoder를 필수 탑재하여 파일을 언팩해야 한다.
