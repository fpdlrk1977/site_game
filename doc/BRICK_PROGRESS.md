## 세션 로그

### 2026-07-29 — 기본값 라인 확정 · 설정 저장 · **P3-a 구운 하늘빛**

**① 기본 돌기 = `line`** (사용자 확정). 5종은 전부 남긴다 — 사용자가 고르게 할 수도 있으므로.
> **선택지로 있는 것과 기본값인 것은 다르다.** 제품의 얼굴(스크린샷·템플릿·대부분의 사용자 콘텐츠)은 기본값이 정한다. 원형을 선택지로 두는 건 어떤 브릭 렌더러에나 있는 형태라 무방하지만, **기본값이면 제품 전체가 레고처럼 보인다.** UI 라벨도 "원형"이지 "레고형"이 아니다.

**② 설정 저장** — `BrickStorage`에 `loadSettings`/`saveSettings` 추가. 청크가 아니라 **월드 단위 설정**이라 별도 키(`brickcfg:*`). 씬 통합 시 `scene_data`로 간다. 브릭을 전부 지워도 설정은 남긴다(사용자가 고른 룩이므로).

**③ P3-a — 면 단위 구운 하늘빛**

> ⚠️ **착수 전 확인한 구조적 제약(사용자 승인)**: 마인크래프트는 청크를 메시 하나로 구워 **정점마다** 빛을 박는다. 우리는 인스턴싱이라 **지오메트리를 공유**하므로 정점별 값을 줄 수 없다.
> → **인스턴스마다 6면의 밝기**를 넘기고 정점 셰이더가 법선으로 고르는 방식. 결과는 마크의 **'Fast 그래픽' 룩**(면마다 밝기가 딱 갈림). **면 내부 그라데이션과 모서리 정점 AO는 불가** — 되돌리려면 인스턴싱을 포기해야 하는데 그건 파츠별 색·클릭 피킹·비큐브 파츠가 전부 무너진다.

- **`world.ts`** — `skyFactor(x,y,z)`(기둥 꼭대기 대비 파묻힌 깊이 → 0..1, 감쇠 15브릭, 최소 0.16) + `faceLight(brick, out)`(면 바로 바깥 칸들의 평균, 월드 순서 `[+x,-x,+y,-y,+z,-z]`). **기존 `colTop` 캐시를 그대로 써서 O(1)** — 빛 격자도 BFS도 없다.
- **`BrickInstances.tsx`** — `aLightA`/`aLightB` 인스턴스 속성 2개(정점 속성은 최대 4성분이라 6개를 vec3 둘로 나눔) + `injectFaceLight` 셰이더. `FACE_MAP`으로 회전(0/90/180/270)에 맞춰 월드 면 → 로컬 슬롯 매핑. **발광 재질엔 안 곱한다**(스스로 빛나므로).
- **★ 지오메트리 공유 함정**: 캐시된 지오메트리는 그룹끼리 공유되므로 거기에 인스턴스 속성을 붙이면 서로 덮어쓴다. → **정점 버퍼는 공유하고 껍데기만 새로** 만드는 얇은 사본(메모리 낭비 없음).
- **실시간 그림자 기본 끔**(P3-c 선반영) + 조명 밸런스 조정(ambient 0.5→0.9, directional 2.2→1.1). 구운 값이 실시간 조명에 뭉개지지 않게.

**P3-a의 한계(의도)**: 깊이 기반이라 **문·창으로 빛이 옆에서 새어 들어오지 않는다.** 창문 있는 방도 균일하게 어둡다. → **P3-b에서 해소.**

### 2026-07-29 — P2-b 청크 스트리밍

12만 브릭 **3초 로딩**을 없앤다. tsc·lint 클린 + 16,214 / 68 / **37** + 라우트 200. **브라우저 확인 대기.**

- **`storage.ts`** — `listChunks()`(**데이터는 안 읽고 목록만**) + `loadChunk(coord)`. 스트리밍의 출발점.
- **`world.ts` `unloadChunk(key)`** — 메모리에서만 내린다. 점유·기둥높이·리전 멤버십까지 함께 정리.
- **`brickStore.streamAround(camX, camZ)`** — 로드 반경 6청크(≈48m) / 언로드 9청크(**히스테리시스** — 경계에서 껌뻑이지 않게). 가까운 청크부터, **24개씩 나눠 읽고 사이사이 양보**해 화면이 안 멈춘다. 배치마다 version을 올려 들어온 만큼 바로 보인다.
- **`loadWorld`가 더 이상 전부 읽지 않는다** — 목록만 만들고 원점 주변부터 스트리밍.
- **`Streamer`**(프로토타입) — 카메라가 4m 이상 움직였을 때만 요청(매 프레임 호출 방지).
- **안개(30~70m, 배경색과 동일)** — 청크가 나타나고 사라지는 경계를 가린다. LOD 대신 쓰는 방식(설계서 §2).

**★ 두 가지 함정과 대응**

1. **언로드는 편집이 아니다.** dirty로 표시하면 **"빈 청크"로 저장돼 실제 데이터가 지워진다.** `unloadChunk`는 dirty를 안 건드리고, 스토어는 **내리기 전에 반드시 `flush()`** 한다.
2. **세로는 전부 올린다.** 아래 청크가 없으면 기둥 높이(`colTop`)가 틀려 **브릭이 허공에 얹힌다.** 스트리밍은 **가로만** 한다(청크가 희소해 세로 전체를 올려도 싸다).

**테스트 +11 (37/37)** — 언로드는 실수하면 조용히 데이터가 사라지는 경로라 집중적으로 잠갔다:
언로드 후 개수·`hasChunk`·**dirty 안 생김**·리전에 유령 안 남음·재로드 복원 · **전부 내리면 기둥 높이도 0**(허공 배치 방지).
※ `unloadChunk`가 dirty를 남기도록 고쳐 보니 **그 항목이 정확히 실패**하는 것을 확인했다.

### 2026-07-29 — P3-b 빛 전파 (BFS)

문·창으로 빛이 옆에서 들어오고, 발광 브릭이 주변을 밝힌다. tsc·lint 클린 + 16,214 / 68 / **26** + 라우트 200. **브라우저 확인 대기.**

**★ 무한 맵인데 BFS가 폭발하지 않는 이유** — 이 설계의 핵심:
> **열린 하늘 칸은 아예 다루지 않는다.** `y >= colTop`이면 항상 최대 밝기라 **O(1)로 답이 나오고**, 저장할 필요도 전파할 필요도 없다.
> BFS는 **그늘진 공기**(구조물 안쪽)만 훑으므로 탐색 범위가 **사용자가 지은 만큼**으로 자연히 한정된다. 야외 씬은 사실상 0, 밀폐 공간만 비용이 든다.

- **`world.ts`** — `light: Map<cellKey, 0..30>`(그늘진 공기만) + `lightAt()`(열린하늘 1 / 막힘·미도달 최소값) + `recomputeLight()`.
  - **레벨별 버킷 큐** — 밝은 버킷부터 처리해 각 칸을 사실상 한 번만 확정. `seed`는 항상 더 낮은 버킷에 넣으므로 순회 중 배열이 커지지 않는다.
  - 씨앗 = 브릭에 맞닿은 그늘 칸 중 ①열린 하늘과 닿은 것(하늘빛 유입) ②발광 브릭 옆(광원).
  - `LIGHT_BUDGET = 400,000`으로 병적인 밀폐 구조에서 멈춘다.
- **`faceLight`가 `skyFactor` → `lightAt`으로 전환** — P3-a의 깊이 감쇠는 폴백으로 남는다.
- **스토어 디바운스(140ms)** — 편집마다 BFS를 돌리면 배치가 끊긴다. 편집이 멎은 뒤 한 번 돌리고 version을 올려 면 밝기를 다시 굽는다. 불러오기·스트레스 직후엔 즉시 계산.
- **통계 패널에 `빛 칸 · 계산(ms)` 노출** — 밀폐 구조를 지었을 때 비용을 눈으로 확인할 수 있게.

**테스트 +8 (26/26)** — 빛은 틀려도 에러가 안 나고 어둡게만 보이므로 "반드시 이래야 하는 것"만 잠갔다:
열린 하늘=1 · 밀폐된 방은 어둡다 · **문을 뚫으면 방이 밝아진다**(P3-a가 못 하던 것) · 문에서 멀수록 어둡다 · 발광 브릭이 밀폐 공간을 밝힌다 · 윗면 > 밑면.
※ BFS 전파를 빼 보니 **3건이 실패**하는 것을 확인했다.

### 2026-07-29 — 돌기 모양 5종 + 놓을 면 격자 가이드 (IP·룩 검토용)

**배경**: "누가 봐도 레고인데 괜찮을까"(사용자). 시각적 차별화 안을 **눈으로 보고 고르도록** 전환 기능으로 구현. 상세 IP 판단은 `BRICK_SYSTEM.md §8.5`.

**돌기 모양 5종** (`brickGeometry.ts` `StudStyle`, 실측 삼각형 — 2×4 기준)

| | 보일 때 | 가려질 때 | 비고 |
|---|---|---|---|
| 원형 | 268 | 12 | 레고와 동일 |
| 링 | 396 | 12 | 가운데 뚫림 — 위에서 가장 구별됨 |

> 🐛 **정정**: "돌기를 없애면 삼각형이 크게 준다"고 했는데 **모따기에선 틀렸다.** 돌기가 없으면 **스터드 컬링이 무의미해져**(가려져도 108 그대로) 밀집 구조에선 원형(268/12 혼합)보다 **총량이 22% 늘어난다.** 삼각형이 실제로 주는 건 **라인 방식(12)** 이다.

**라인 방식 — 확대/축소에 안 깨지게** (사용자 질문): 선 두께를 UV가 아니라 **화면 미분(`fwidth`)** 으로 잡는다.
- 확대해도 굵어지지 않고 축소해도 사라지지 않음(항상 ~1.2px) · `smoothstep`으로 안티에일리어싱
- **멀어지면 선을 지운다** — 안 그러면 선이 뭉쳐 벽 전체가 거뭇해진다(모아레)
- `vUv`는 텍스처가 없으면 three가 안 만들어 준다 → `#define USE_UV` 주입(three 0.185 지원 확인)
- 지오메트리는 민짜 상자 12삼각형 그대로 — 선은 **픽셀 단계에서만** 그린다

**신규 `PlacementGrid.tsx` — 놓을 면 격자 가이드**
> 사용자 피드백: *"돌기가 없으니 어디에 놓아야 할지 애매하다."*
> **돌기는 장식이 아니라 격자를 눈에 보이게 하는 장치였다.** 없애면 반드시 대체가 필요하다.

브릭이 앉을 **밑면 높이**(anchor.y)에 격자 판(삼각형 2개)을 커서 따라 띄운다. 월드 좌표 기준이라 실제 셀에 정확히 맞고, 라인과 같은 `fwidth` 기법이라 확대/축소에 일정하다. 가장자리 페이드로 하드컷 방지, 멀면 사라짐. `useFrame`으로 위치만 갱신(리렌더 없음), `raycast=null`.
**고정 모드에선 미표시** — 작업 평면 격자가 이미 같은 일을 한다(중복 방지).

### 2026-07-29 — P2-a 리전 배칭 (프러스텀 컬링 살리기)

12만 브릭 실측이 가리킨 병목을 고쳤다. tsc·lint 클린 + 테스트 16,214 + 68 + 18 + 라우트 200. **브라우저 재측정 대기.**

**의도적으로 포기한 것(사용자 승인)**: **옆면 붙이기·아래 매달기.** 이제 브릭은 항상 발밑으로 내려앉는다. → 곧바로 아래 "높이 고정 모드"로 보완했다.

#### 🔒 높이 고정 모드 (같은 날, 사용자 요청)

드롭 모델이 못 하는 일 — **받쳐줄 게 없는 자리**(천장·2층 바닥·다리 상판·창문 위 인방) — 을 메우는 보조 모드.

| | 드롭 모드(기본) | 높이 고정 모드 |
|---|---|---|
| 높이 | 발자국 아래에서 자동(`restY`) | **사용자가 지정(`lockY`)** |
| 공중 배치 | 불가 | **가능** |
| 겹침 | 구조적으로 불가 | 겹치면 빨강(막힘) |

- **스키마/스토어**: `lockY: number | null`(null=드롭) + `toggleLock(currentY)`(현재 고스트 높이로 잠금·재누르면 해제) + `nudgeLock(±1)`(한 단 = 브릭 높이 3칸). `clampLock`으로 0~`Y_MAX` 안에 가둔다.
- **배치 규칙**: `anchorFromPointer(..., lockY)` 한 곳에서 `lockY ?? restY(...)`로 분기. **규칙이 여전히 한 곳에만 있다.**
- **작업 평면**: 고정 시 그 높이에 투명 레이캐스트 평면(400×400) + 파란 격자를 띄운다. **고정 모드에선 XZ를 이 평면에서만 받는다** — 브릭 표면에서 받으면 높이가 달라 커서와 고스트가 시차로 어긋난다(브릭·바닥 hover 핸들러를 `locked`로 게이트).
- **조작**: `L` 토글 · `PageUp/PageDown` 층 이동 · 좌측 패널에 `N층 · N.Nm` 표시와 ± 버튼.
- **테스트 +9** (총 16,214) — 기둥 두 개 사이 빈 공간에서 드롭은 바닥(0)으로 떨어지고 고정은 지정 높이 유지 · XZ 불변 · 겹치면 배치 불가 · 지형이 달라도 고정 높이 유지.

### 2026-07-29 — 🐛 확장 배치 평면 (커서 도달 범위 = 배치 가능 범위)

**사용자 보고**: "2×4를 바닥에 놓고 그 **돌기 끝부분**에 2×4를 끼우려 하면, 마우스 포인터가 아래 브릭을 벗어나면서 끼울 수 없다."

**원인**: 자유 축 좌표를 아래 브릭 **표면의 레이캐스트 지점**에서만 얻고 있었다. 여러 칸짜리 브릭은 아래 브릭에 **한 칸만 걸치는 위치**까지 유효한데, 커서는 아래 브릭 표면 위에만 머물 수 있어 바깥쪽 자리에 도달을 못 했다. 커서가 브릭을 벗어나는 순간 레이가 바닥 평면에 맞아 y=0으로 떨어졌다.
→ **커서가 갈 수 있는 범위가 놓을 수 있는 범위를 잘라먹고 있었다.** 1×1 블록(마인크래프트)에선 생기지 않는, 다중 칸 파츠 고유의 문제.

**수정**:
1. **`BuildPlane`**(신규, `BrickPrototype.tsx`) — 접촉면을 **닿을 수 있는 모든 위치만큼**(각 축 ±(새 브릭 길이−1)칸) 넓힌 투명 평면. 브릭 표면보다 **0.002m 안쪽**에 둬서 브릭 위에서는 브릭이 먼저 잡힌다(면 판정 유지). 살짝 보이게(opacity 0.07) 해서 "여기까지 놓을 수 있다"가 눈에 보인다.
2. **`face`를 hover 상태에 고정** — 확장 평면 위의 좌표는 브릭 AABB **바깥**이라, 거기서 `faceOf`를 다시 부르면 엉뚱한 면이 나온다. 브릭에 처음 닿은 순간 확정해 들고 다닌다.
3. 브릭 `onPointerOut`의 `null`을 무시 — 바닥/확장 평면 이벤트가 곧바로 갱신하므로 깜빡임 방지.

#### 🐛 후속 — 확장 평면이 "반쪽만" 되던 문제 (같은 날)

**사용자 보고**: "위는 되는데 아래는 안 되고, 오른쪽은 되는데 왼쪽은 안 된다. 반쪽만 된다."

**원인 — 규칙이 두 군데에 따로 적혀 있었다.** `placement.ts`의 `centered()`는 가리킨 칸에서 `floor((길이−1)/2)`만큼 당겨 앵커를 잡는데, `BuildPlane`은 그 보정을 모른 채 평면을 깔았다. 그래서 도달 범위가 **한 칸씩 밀려서** 한쪽 끝은 못 가고, 반대쪽은 **아예 닿지도 않는 자리(공중 배치)까지** 갈 수 있었다.
- 2×4 기준: 필요한 앵커 [−3…+3] ↔ 실제 도달 [−4…+2]
- 짧은 축(길이 2)은 보정이 0이라 멀쩡했다 → **긴 축에서만 티가 나는 비대칭**

**수정**: `placement.ts`에 **`centerOffset()`·`reachRange()`를 단일 기준점으로 export**하고 `BuildPlane`이 그걸 쓰게 했다. 이제 규칙이 한 곳에만 있다.

**테스트 `placement.test.ts` 1544/1544** (`npx tsx src/lib/brick/placement.test.ts`)
불변식 하나를 고정한다 — **커서가 갈 수 있는 범위 == 아래 브릭에 닿을 수 있는 앵커 범위.**
파츠 4종 × 회전 4 × 파츠 4종 × 회전 4 × 좌표 3곳 × 2축 전수 + 신고 케이스(2×4 위 2×4의 ±3 끝자리 도달, ±4 공중자리 차단).
※ 옛 공식으로 되돌려 **184건 실패**하는 것을 확인했다(테스트가 실제로 이 버그를 잡는다).

**미해결(후속)**: **옆면(±x/±z)은 확장 평면이 없다.** 벽을 따라 어긋쌓기할 때 같은 제약이 남는다(브릭 자체 길이 안에서만 어긋낼 수 있음). 수직 평면이라 카메라 방향에 따라 epsilon 부호가 갈려서 P0 범위에서 제외했다. 벽 쌓기에서 불편하면 그때 추가.

**덤**: Canvas `shadows` → `shadows="percentage"`(three가 PCFSoftShadowMap을 deprecate — 기존 `ViewerCanvas`와 동일하게 맞춤).
