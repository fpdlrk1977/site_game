# UI_REDESIGN — 디자인 리뉴얼 방향 & 실행 스펙 (기준 문서)

> 목적: 현재 UI가 "노멀·특색 없음"인 원인을 진단하고, **심플·트렌디·디자이너 우선**으로 리뉴얼하는 방향과 **코드로 바로 옮길 토큰 값**을 남긴다.
> 사용자 결정 대기: **①액센트 색 ②다크/라이트 기본** — 정해지면 Step 1부터 바로 착수(아래 값 사용). 결정 전까지 **추천값(바이올렛·다크우선)**을 기본으로 문서화.
> 타겟: 일반인 + **다수의 디자이너**. 참고 아티팩트(이 세션): claude.ai UI 방향 제안(진단·벤치마킹·토큰).

## 도출 과정 — 결론이 나온 논리 (왜 이런 결과인가)

> 아래 진단/원칙/토큰이 "그냥 취향"이 아니라 **관찰에서 단계적으로 도출**됐음을 남긴다. 나중에 결정을 재검토할 때 이 체인을 따라가면 된다.

**1) 관찰 → 진단** (증거는 코드 + 사용자 피드백)
- `globals.css`를 실제로 열어 토큰 확인 → Primary가 정확히 `#2563EB`. 이건 **Tailwind blue-600 기본값**이자 부트스트랩 이후 SaaS가 가장 많이 쓰는 색. "어디서 본 듯함"의 물리적 원인.
- 중립색이 순수 slate 램프(`#64748B` 등) = Tailwind 기본 팔레트 그대로 → "직접 고른 색이 아니라 **물려받은 색**" = 정체성 부재.
- 그런데 로고·저장버튼 코드엔 `from-violet-500 to-cyan-500`(보라) → **브랜드는 보라, UI는 파랑 = 불일치**(브랜드색을 시스템에 반영 안 한 것).
- 컴포넌트가 `text-[10px]/[11px]` + 곳곳 `border` + 인스펙터 전 섹션 상시 노출 → 사용자 불만("세세한 것까지 노출돼 집중 안 됨")과 코드가 일치 → 주관 아닌 **구조적 문제**로 확정.

**2) 진단 → 벤치마킹 선정 기준**
- "특색 없음"의 해법은 발명이 아니라 **디자이너가 실제 신뢰하는 툴이 이미 푼 방식**을 가져오는 것.
- 그래서 우리 약점 하나씩에 대응하도록: 디자이너 표준(**Figma**=크롬 절제) · 트렌디 미니멀 정점(**Linear**=톤 단차/다크) · 직접 경쟁·같은 3D(**Spline**=친근한 라운드) · 타이포/친근 축(**Framer·Womp**). "각자에게서 하나만" = 짜깁기 아닌 명확한 차용.

**3) 벤치마킹 → 원칙** (각 원칙의 출처)
- 캔버스 우선 ← 3D 툴인데 파란 크롬이 시선 뺏음 + Figma.
- 점진적 공개 ← 사용자 핵심 불만(디테일 과노출) + 인스펙터 밀도 진단.
- 시그니처 색 하나 ← blue-600 국민색 + 브랜드 불일치 → 보라로 통일.
- 차분한 밀도 ← 10px 초밀도 + Linear/Framer 여백.
- 테두리 대신 단차 ← border 남발 + Linear 톤 단차.
- 의도된 모션 ← (예방) 장식 모션 = "AI 티" → 트렌디함과 반대.

**4) 원칙 → 토큰 결정 근거**
- **액센트=바이올렛(추천)**: 이미 브랜드가 violet-cyan → 새 색 발명보다 **브랜드를 UI에 일치**시키는 게 리스크 최소·정체성 최대. (코럴/라임은 더 튀지만 브랜드 재정의가 필요 = 그래서 대안으로만.)
- **다크 우선**: 3D 뷰포트는 어두운 배경에서 형태·재질이 더 잘 읽힘(=캔버스 우선 원칙의 물리적 귀결) + 창작 툴은 장시간 작업→눈 피로↓·"프로" 인상. Blender·Spline·Linear 다 다크 기본.
- **radius↑·밀도↓**: Spline 친근함 + 부드러운 모서리 트렌드 + 밀도 진단.
- **왜 `globals.css`부터(Step 1)**: 색·radius·밀도가 전부 CSS 변수 단일 소스 → **한 파일 교체로 전역 반영** = 최소 코드·최대 체감·되돌리기 쉬움(저위험).

**5) 실행 순서 근거**: 위험/의존성 오름차순 — 토큰(전역·저위험) → 크롬(구조 손 안 댐) → 인스펙터 점진공개(방금 컴포넌트화 덕에 가능) → 시그니처(선택적 마무리).

## 진단 — 왜 특색이 없나 (코드 근거: `src/app/globals.css`)

1. **가장 흔한 색**: Primary `#2563EB`(Tailwind blue-600) = 국민 SaaS 색. 중립색도 순수 slate(`#64748B` 등) → 정체성 0.
2. **브랜드 불일치**: 로고·저장버튼은 `violet→cyan` 그라데이션인데 UI 전체는 파랑 → 톤이 "업무 대시보드".
3. **테두리 남발 + 초밀도**: 거의 모든 요소에 `border`, 본문 `10~11px`. 빽빽해서 피곤.
4. **디테일 상시 노출**: 인스펙터가 Transform·Material·Physics·Motion·Events·Array·Prefab을 한 번에 → 집중 방해(사용자 핵심 불만).

## 벤치마킹 (각자에게서 하나씩만)

- **Figma** → 조용한 크롬(패널이 물러나 캔버스가 주인공).
- **Linear** → 테두리 대신 **표면 밝기 단차** + 다크 우선 + 넉넉한 여백("비싸 보임").
- **Spline**(경쟁) → 큰 라운드 모서리 + 통제된 컬러 + 부드러운 그림자(친근한 3D 감성).
- **Framer/Womp** → 자신 있는 타이포 위계 · 라운드 미니멀(일반인·디자이너 다리).

## 디자인 원칙 6 (리뉴얼 판단 기준)

1. **캔버스 우선** — 크롬은 회색조로 물러나 3D 씬이 유일한 컬러.
2. **점진적 공개** — 기본 최소 노출, 고급 파라미터는 접기.
3. **하나의 시그니처 색** — 파랑 탈출, 액센트 1종 절제 사용(그라데이션 남발 금지).
4. **차분한 밀도** — 본문 10→13px, 여백↑, 히트 영역↑. 위계로 프로처럼.
5. **테두리 대신 단차** — border↓, 표면 밝기·그림자로 영역 구분.
6. **의도된 모션** — 패널 열림·상태 전환에만 짧게(장식 애니 금지 = AI 티).

## 제안 토큰 (코드로 바로) — `src/app/globals.css` 변수 교체

> 컴포넌트 수정 거의 없이 **전역 즉시 반영**. 아래는 **다크 우선 + 바이올렛(추천)** 기준. 색/테마 확정 시 이 표대로 치환.

### 중립색 (slate → 바이올렛-편향)
| 토큰 | 현재(light) | 제안(light) | 현재(dark) | 제안(dark) |
|---|---|---|---|---|
| `--background` | #F6F7F9 | **#F7F6FB** | #111317 | **#0E0D13** |
| `--surface` | #FFFFFF | #FFFFFF | #181B21 | **#17161F** |
| `--sidebar` | #FBFBFC | **#FBFAFE** | #14171C | **#131219** |
| `--canvas` | #EEF1F4 | **#EDEBF3** | #0D1015 | **#0A0910** (더 어둡게=3D 강조) |
| `--border` | #E8EBEF | **#E7E4F0** | #252B34 | **#262430** (사용 빈도↓) |
| `--foreground` | #0F172A | **#16141E** | #F8FAFC | **#EDEBF4** |
| `--muted` | #64748B | **#6C6979** | #94A3B8 | **#8E8B9E** |

### 액센트 = `--primary` (파랑 대체) — **하나 선택**
| 안 | light | dark | 성격 |
|---|---|---|---|
| **바이올렛 (추천)** | **#6A4DFF** | **#7C6CFF** | 기존 브랜드 계승, 크리에이티브, 가장 안전 |
| 웜 코럴 | #F0503F | #FF6B5C | 차가운 중립 위 온기 = 의외성·친근, 확실한 차별 |
| 일렉트릭 라임 | #A6D42E | #C4F04A | near-black 위 형광, 대담·취향 강함(음악/3D툴 감성) |

### 모서리 (부드럽게) + 밀도
- `--radius-xs: 6 → 8px`, `sm: 8 → 10`, `md: 12 → 14`, `lg: 16 → 18`.
- 밀도: 인스펙터 본문 라벨 `10~11px → 12~13px`, 섹션 패딩·행 높이 +20~30%. 수치는 `tabular-nums` 유지.
- 반응: `--primary` 다크값이 밝아 라이트 배경 대비 확인(코럴/라임은 라이트에서 더 어둡게 = 위 표 반영).

## 실행 계획 (위험 낮은 것부터)

- **STEP 1 — 토큰 교체** (`globals.css` 변수): 위 표대로 색·radius·밀도. 컴포넌트 거의 무수정, 전역 즉시. **저비용·최고 즉효.** ← 색/테마 확정 후 바로 여기부터.
- **STEP 2 — 크롬 정리**: `ViewportToolbar`·`EditorGnb`·좌우 패널의 border↓ → 단차·그림자, 여백↑. 상단 툴바·GNB를 회색조로 눌러 캔버스 강조.
- **STEP 3 — 인스펙터 점진적 공개**: 각 섹션 "기본/고급" 분리(Transform·색만 먼저, 물리·이벤트 고급값 접기) + 접힘 상태 기억. **방금 `panels/inspector/` 컴포넌트화(3855→277줄)로 붙이기 쉬움.**
- **STEP 4 — 시그니처 모먼트**: 빈 상태·온보딩·플레이 토글·에셋 카드에 브랜드 액센트·부드러운 모션. "예쁘다" 지점.

## 결정 대기 (Step 1 착수 전 확정)
1. **액센트 색**: 바이올렛(추천) / 웜 코럴 / 일렉트릭 라임
2. **기본 테마**: 다크 우선(추천) / 라이트 우선 유지

## 연계
- P0 UX(오토세이브·인에디터 플레이·게임/로직 탭·Undo/Redo 노출·인스펙터 탭 분리)와 병행 가능. **STEP 3(점진적 공개)은 P0 "인스펙터 탭 분리"와 사실상 동일 작업** → 함께 처리 권장.
- 다크 우선으로 가면 라이트도 정제해 유지(뷰어 토글 지원 규칙 준수).
